# 2026 BP·WP·AX 경진대회 — 무대 송출 슬라이드 설계 스펙

작성일 2026-06-30. 상태 = 설계 승인됨(사용자), 스펙 리뷰 대기.

## 1. 개요·목적

행사 무대에 송출하는 **인터랙티브 HTML 프레젠테이션 2종**을 만든다. 기존 심사 채점 웹앱(`scoring-system` 스킬의 judge/admin)과는 별개의 **행사용 발표 자산**이며, 재사용 스킬을 더럽히지 않도록 이 폴더에 독립으로 둔다.

- **안내 덱(`guidance.html`)** — 각 법인 발표 후 "심사 평가 시간" 시작 시 무대에 송출. 채점 페이지 접속 QR·주소, 입력 방법 안내, 차분한 BGM. 평가 시간 동안 떠 있는 화면.
- **시상 덱(`awards.html`)** — 사회자가 시상을 발표할 때 무대에 송출. 어두운 무대에서 극적 애니메이션으로 한 명씩 공개.

대상 환경: 무대 노트북 + 크롬 전체화면 + 프로젝터(16:9). 운영자가 클리커/키보드로 제어.

## 2. 공통 설계

- **단일 파일 HTML 2개.** QR·컨페티 등 라이브러리를 인라인(또는 vendored 로컬)해 **오프라인 실행** 가능. 무대 노트북에 파일만 복사하면 동작. (예외: BGM 음원은 `assets/` sibling 파일, awards 라이브 집계는 인터넷 필요 — 4·5절.)
- **해상도** 1920×1080(16:9). CSS로 뷰포트에 스케일(글자·요소가 화면을 꽉 채우되 비율 유지).
- **테마** 다크 스테이지(near-black 배경) + Rausch `#FF385C` 포인트, 시상은 골드 `#E0A100`. Pretendard 폰트(로컬 폴백 `맑은 고딕`). 기존 Airbnb 톤과 브랜드 연속성 유지하되 무대용으로 어둡게.
- **제어키(두 덱 공통)**: `→`/클릭/`Space`(첫 입력은 시작+BGM 게이트) = 다음, `←` = 이전, `F` = 전체화면 토글, `B` = 블랙아웃. 운영자가 사회자 멘트 페이스에 맞춰 한 단계씩 진행.
- **자동재생 정책 대응**: 브라우저가 소리 있는 자동재생을 첫 사용자 제스처 전까지 차단하므로, 운영자가 `Space`로 "시작"하면 그때 BGM이 재생되도록 게이트를 둔다.

## 3. 안내 덱 (`guidance.html`)

평가 시간 내내 떠 있는 화면. 레이아웃을 좌우로 나눈다.

- **고정 영역(좌, 또는 우)**: 접속 **QR + URL 텍스트**를 크게 상시 노출(심사위원이 폰으로 찍는 동안 계속 보이게). QR은 CONFIG의 judge 공개 URL에서 **클라이언트로 생성**(주소만 바꾸면 자동 갱신).
- **회전 영역**: 입력 4스텝을 자동 회전·루프 — ① 분야 선택(BP/WP/AX 칩) → ② 평가 대상 팀 카드 → ③ 각 항목 **1~5점 버튼** → ④ 제출. 각 스텝은 raster 스크린샷이 아니라 **judge.html UI를 본뜬 미니어처**(다크 톤으로 재스타일)로 그려 큰 화면에서도 또렷하게.
- **안내 칩**: "본인 소속 팀은 자동으로 평가 대상에서 제외됩니다", "각 항목 1~5점, 가중치로 100점 환산".
- **BGM**: 차분한 트랙 루프(5절).
- **진행**: 기본 자동 회전(루프). 운영자가 수동으로 넘길 수도 있음.

전제: QR이 실제로 동작하려면 judge.html이 공개 배포돼 URL이 있어야 한다(7절).

## 4. 시상 덱 (`awards.html`)

### 4.1 리빌 순서
- 분야 순서: **WP → BP → AX** (사용자 지정. 참고: config의 `ceoReportOrder`는 BP·AX·WP이지만 무대 발표 순서는 별도로 WP→BP→AX를 따른다.)
- 각 분야 내부: **하위 상 먼저 → 대상 마지막**(드라마틱 빌드업). config `awards` 기준 —
  - WP: 대상(1등) 1개 → 대상만 공개.
  - BP: 우수상(2등) → 대상(1등).
  - AX: 우수상(3등) → 우수상(2등) → 대상(1등).
  - 즉 "있는 상만, 랭크 낮은 것부터" 자동 구성.

### 4.2 한 수상의 연출 흐름
분야 인트로(어둡게, 분야명·부제) → 서스펜스("…"/심박 비트) → **공개**: 팀명 슬램 인 + 스포트라이트 + 메달(🥇/🥈/🏅), **대상엔 컨페티 버스트** → 팀·중앙값 점수(100점 만점)·상금 표시. 운영자 클릭으로 다음 단계.

### 4.3 라이브 직접 집계 (사용자 결정)
- awards.html이 **admin과 동일하게** Apps Script `apiUrl`로 제출 데이터를 JSONP fetch → 그 자리에서 **중앙값·동률(대표이사 120% 가중)·본인 소속 제외**를 계산해 분야별 순위·상금을 만든다.
- **무대 인터넷 의존**을 받아들이되, **열 때 1회 fetch → 메모리 스냅샷**으로 이후 리빌을 진행한다. 발표 도중 네트워크가 끊겨도 화면은 안 깨진다. 운영자용 "결과 새로고침" 버튼과 마지막 동기화 시각 표시.
- **정합성(중요·고위험)**: 무대에서 오답을 부르면 안 되므로 awards의 집계는 **admin과 동일한 단일 알고리즘**을 쓴다. 알고리즘을 공유 모듈로 두고 단일 파일에 인라인하며, **parity 테스트**(`scoring-system` validate 하니스의 담합 더미 데이터로 admin과 awards의 분야별 순위가 동일함을 단언)를 둔다.

## 5. BGM (로컬 음원, 사용자 결정)

- 사용자가 지정한 트랙(`https://www.youtube.com/watch?v=U34kLXjdw90`)을 **로컬 음원 파일로 내려받아** `assets/bgm/`에 두고 `<audio loop>`로 재생. 오프라인·무광고·페이드/볼륨 제어 정확.
- CONFIG `bgm.mode = 'file' | 'youtube'` 둘 다 지원하되 **기본은 file**. (`youtube` 모드 = 숨긴 IFrame 오디오, 인터넷·광고 리스크가 있어 비상용.)
- 안내 덱은 차분한 루프. 시상 덱은 같은 트랙 또는 별도 트랙 슬롯(운영자가 교체 가능). 내부 행사 사용의 저작권 판단은 운영자 몫(스펙에 명시만).

## 6. 파일 레이아웃

```
2026-경진대회-무대슬라이드/
  guidance.html        # 안내 덱(단일 파일)
  awards.html          # 시상 덱(단일 파일)
  config.js            # 공유 설정(apiUrl, judgeUrl, teams, categories, awards, tieRule, bgm 등) — 두 덱이 읽음
  assets/
    bgm/…              # 내려받은 BGM 음원
  test/
    parity.mjs         # awards 집계 == admin 집계 단언(담합 더미)
  README.md            # 운영 가이드(실행·제어키·결과 동기화·BGM 교체·전제조건)
  docs/specs/…         # 본 스펙
  docs/plans/…         # 구현 계획(다음 단계)
```

config는 `scoring-system`의 `config.template.json`에서 무대에 필요한 키(apiUrl·teams·categories·awards·tieRule·event)를 가져와 일치시킨다(진실원은 행사 config).

## 7. 전제조건(행사 전 운영자 작업)

- **judge.html 공개 배포 URL** — 안내 덱 QR이 가리킬 주소. GitHub Pages 등(setup-guide 참고). 현재 미확보.
- **Apps Script `apiUrl`(/exec)** — awards 라이브 집계 fetch 대상. 현재 config는 placeholder. Google Sheet + Apps Script 배포 후 확보.
- 위 두 값은 `config.js`에 넣는다. 값 확보 전에는 더미 URL로 개발하고, 확보 후 교체.

## 8. 비범위 (YAGNI)

- 발표자 노트, 다국어, 인쇄용 PDF, 관리자 인증 — 무대 송출 1회용이라 만들지 않는다.
- 시상 결과 수동 입력 UI — 라이브 집계로 결정됐으므로 두지 않는다(비상용 수동 오버라이드는 README 절차로만).
- 영상 렌더(mp4)·PPTX 변환 — 인터랙티브 HTML로 확정.

## 9. 검증 방법

- **parity.mjs**: awards 집계 결과가 admin과 동일(담합 더미에서 실력팀 1위, 동률·recusal 동일) — exit 0 게이트.
- **수동 리허설**: 더미 제출 데이터로 awards를 끝까지 클릭, WP→BP→AX·하위상→대상 순서와 컨페티·BGM·블랙아웃·네트워크 끊김 스냅샷 동작 확인.
- **안내 덱**: 더미 judge URL로 QR 스캔→해당 주소 열림 확인, 4스텝 회전·BGM 게이트 확인.
- 1920×1080 전체화면에서 글자 잘림·오버플로우 없음 확인.
