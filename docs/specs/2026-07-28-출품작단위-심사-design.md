# 출품작(entry) 단위 심사 전환 — 설계 (2026-07-28 확정)

## 배경·문제

기존 시스템은 "6개 법인 × BP·WP·AX 각 1건" 전제로 점수를 `scores[부문][팀명]`에 저장했다.
실제 접수 결과 법인별 출품이 고르지 않아(중국 BP 2건·AX 0건, AX추진실 AX 5건 등) 이 전제가 깨졌다.

- 심사위원이 발표하지 않은 조합(예: 중국 AX)을 채점하게 됨.
- 같은 법인의 복수 출품(중국 BP 2건)을 구분할 수 없음.
- 발표는 법인별 20분 슬롯인데 채점 화면은 부문(BP→WP→AX) 단계라 심사위원이 화면을 오가야 함.

## 확정 결정 (사용자 승인)

1. **채점 단위**: 팀 → **출품작(entry)**. 점수 키는 `scores[부문][entryId]`.
2. **채점 화면**: 부문 3단계 → **법인 6단계(발표 순서)**. 각 단계에 해당 법인의 출품작 카드만 표시.
3. **발표 순서**: 중국법인 → 태국법인 → 이집트법인 → 한국사업부 → AX추진실 → HQ.
4. **채점 방식**: 항목별 채점 유지 (BP·WP 6항목, AX 4항목, 가중치 100점 환산 — 이미 공지된 루브릭).
5. **수상 정책**: **법인당 부문별 1건 제한** — 부문 순위에서 같은 법인의 두 번째 이하 출품작은 수상 후보에서 건너뜀.
6. **팀명 변경**: 기술연구소 → **AX추진실**. (심사위원 명단의 "기술연구센터장" 직함은 실제 직함이므로 유지.)
7. 집계 원칙 유지: 중앙값 공식점수 · 본인 소속(법인) 제외 · 동률 시 대표이사 120% 가중 · 이상패턴 탐지.

### 2026-07-29 변경 이력

- AX추진실 출품이 AX 5건 → **BP 1건 + AX 1건**으로 축소(`AXD-AX1`~`AXD-AX5` 폐기, `AXD-BP1`·`AXD-AX1` 신설). 오프닝 rundown 16:20 항목도 "BP · AX 발표 — AX추진실"로 정정.
- 한국사업부 6건은 내용 변경 없이 **배열 순서만 실제 발표 순서(김해 BP·WP·AX → 창원 BP·WP·AX)로 재배치**. id는 유지.
- `onePerTeam` 하에서도 시상 슬롯이 비지 않음을 확인 — BP 5개 법인/2슬롯, WP 4개 법인/1슬롯, AX 5개 법인/3슬롯.

## 데이터 모델 (config.json)

```json
"teams": ["중국법인","태국법인","이집트법인","한국사업부","AX추진실","HQ"],   // = 발표 순서
"teamShort": {"중국법인":"중국","태국법인":"태국","이집트법인":"이집트","한국사업부":"한국","AX추진실":"AX실","HQ":"HQ"},
"entries": [ {"id":"CN-BP1","team":"중국법인","cat":"BP","title":"...","sub":""}, ... ],
"awards": { "onePerTeam": true, "default":[...], "WP":[...], "AX":[...] }
```

- 제출 페이로드는 기존과 같은 3키 구조(`scores.BP/WP/AX`)를 유지하되 내부 키만 entryId. Code.gs(백엔드) 수정 불필요.
- 팀명으로 키잉된 과거 테스트 제출은 집계에서 자연히 null 처리되지만, 행사 전 시트 초기화 권장.
